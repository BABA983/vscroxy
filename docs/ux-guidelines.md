# vscroxy UX 规范

状态：已定稿，实施时细化。本文规定"界面怎么工作、怎么说话"。视觉规范（字号、颜色、组件外观）见 [UI 设计规范](ui-redesign.md)，功能范围见 [功能路线图](feature-roadmap.md)，代码怎么支撑这些规范见 [基础设施方向](architecture.md)。

新功能和改版都按本文做；第 12 节是评审清单。

## 1. 核心任务

按使用频率排序。设计冲突时，排在前面的任务优先：

1. 看到某个 App 或某个域名的请求。
2. 找到出错的、慢的、可疑的那一条，看懂它。
3. 改一下再发一次（在检查器里原地编辑，Send）。
4. 改响应、mock、断点，验证客户端的行为。
5. 切换 host 或环境，把同一个客户端指到别的服务器。
6. 把请求整理成集合、写断言、反复运行。

前两项要做到零学习成本：装好就能抓，点一下就能看懂。

## 2. 原则

1. **当前状态一眼可见。** 所有会改变流量的开关（断点、限速、No Caching、Scenario、Host 方案、上游代理、白名单）启用时都必须在主界面上看得到，并且一步就能关掉。用户永远不应该因为"忘了某个规则还开着"而浪费时间。
2. **能就地完成就不弹窗。** 弹窗只用于必须先完成、再回到原处的短任务（见第 4 节）。
3. **同一个对象，同一套动作。** 一条流量、一个请求、一个集合，不管从右键菜单、`⋯` 菜单、命令面板还是快捷键进入，动作的名字、顺序、可用条件都一样。
4. **能撤销就不确认。** 本地可恢复的操作直接执行，给撤销；只有对外部有影响、或不可恢复的操作才先确认（见第 7 节）。
5. **界面只说一句话。** 解释性文字放进 tooltip、"了解更多"和文档；界面上不出现成段的说明。
6. **键盘和鼠标同样完整。** 每个动作都能用键盘完成，常用动作有快捷键，所有动作都能在命令面板里找到。
7. **不替用户做有后果的决定。** 不自动发送请求、不自动改系统设置、不自动删除数据。这一条现有代码已经做得很好，继续保持。

## 3. 信息架构

| 位置 | 放什么 |
| --- | --- |
| 标题栏 | 品牌、录制状态（含暂停按钮、监听地址和速率曲线）、命令栏（`⌘K`，同时是搜索）、左右／上下布局切换、Host 方案切换、Tools、Settings |
| 已启用工具栏 | 标题栏下方的一条窄栏，只在有工具启用时出现，见第 5 节 |
| 工作区（只有一个） | 侧栏三组：LIVE（流量分类、App、域名、保存的筛选）、COLLECTIONS（集合树）、SESSIONS；中间栏：流量列表（查询栏、活动柱状图），或选中已保存请求时的发送历史；详情：请求文档（抓到的和保存的是同一种）和响应。环境、APIs、Runner 从集合菜单和命令面板进入。见 [UI 设计规范](ui-redesign.md) 第 3 节 |
| Tools 窗口 | 规则（Map Local、Map Remote、Block、断点）、Scenario、规则脚本、Host 方案、Mock。经常开关的东西 |
| Settings | 很少改的配置：通用、外观、代理、HTTPS、抓包、设备 |
| 命令面板 | 所有动作，包括上面每个位置里的动作 |

判断一个新功能放哪里：

- 针对一条流量或一个请求的操作 → 放在那个对象的动作里（第 6 节）。
- 会经常开关、影响后续流量 → Tools。
- 设一次就很少再动 → Settings。
- 一次性的流程（导入、导出、整理成集合）→ 向导或弹窗，入口放在对象动作和命令面板里。

## 4. 交互模式的选择

| 模式 | 什么时候用 | 例子 |
| --- | --- | --- |
| 就地编辑 | 修改当前看到的一个值 | 重命名请求、改列宽、编辑 header 单元格 |
| Popover | 轻量选择或 1–3 个字段，点外面就关闭 | 方法选择、列选择、颜色标记、快速筛选 |
| 侧边抽屉 | 需要同时看着主内容的辅助编辑 | 变量预览、请求的 Examples、规则详情 |
| 弹窗 | 必须先完成再回到原处的短任务；不超过一屏 | 新建集合、确认破坏性操作、导入报告 |
| 向导（弹窗内分步） | 有多个依赖步骤、每步需要预览 | 整理成集合、首次启动引导、设备接入 |
| 独立窗口或页面 | 长时间编辑、管理一类资源 | Tools、Settings |

规则：

- 弹窗不叠弹窗。需要第二层时，改成抽屉或独立页面。
- 弹窗里的主操作在右下角，取消在它左边；Esc 等于取消。
- 不能因为点了弹窗外面就丢掉用户输入；有未保存内容时点外面不关闭。
- 断点弹窗是例外：它对应正在挂起的真实请求，Esc 和点外面都不能中止请求（现有行为，保持）。

## 5. 状态可见性

### 录制状态

标题栏中间的 pill 显示三种状态之一，并带一个暂停/继续按钮：

- **Recording · 127.0.0.1:7890**（绿点）。
- **Paused**（灰点）：代理继续转发，但不记录新流量。
- **Proxy stopped**（红点）：监听失败，点开看原因。

设备接入开启时，pill 后面加 **LAN**。

### 已启用工具栏

任何改变流量的工具启用时，标题栏下方出现一条窄栏，每个工具一个 chip，例如 `Breakpoints` `3G` `No Caching` `Scenario: Empty cart` `Hosts: 测试` `Upstream`。

- 点 chip 的主体：打开它在 Tools 或 Settings 里的位置。
- 点 chip 上的 ×：关闭这个工具。
- 全部关闭时这条栏消失。
- 命中过规则的流量，在列表里有标记，在检查器里有"Applied"一行说明是哪条规则（现有行为，保持）。

### 状态栏

左边：已抓数量、显示数量、选中数量。右边：auto-follow、当前环境（选中已保存请求时）。不放会过期的消息；消息走 toast（第 8 节）。

## 6. 对象动作

所有入口从同一张动作表生成（实现见 [基础设施方向](architecture.md) 的"动作层"）。右键菜单按以下分组和顺序排列，不可用的动作显示为禁用，而不是隐藏；命令面板里会说明为什么不可用。

**一条流量：**

1. 下一步：Replay、Edit request、Save as request、Add to collection…
2. 复制：Copy URL、Copy as cURL、Copy response body、Copy as…
3. 整理：Pin、Mark…、Add note
4. 工具：Breakpoint、Map Local、Map Remote、Block、Map this host…、HTTPS inspection
5. 视图：Filter by this host、Filter by this app、Open in browser
6. 危险：Remove from list

**一个已保存的请求：** Open、Send、Duplicate、Rename、Move to…、Copy as cURL、Generate code…、Delete

**一个集合或文件夹：** New request、New folder、Run…、Settings…、Export…、Rename、Delete

多选时，只显示能对整个选择生效的动作，标签写明数量，例如 "Replay 5 requests…"。

## 7. 撤销和确认

| 操作 | 方式 |
| --- | --- |
| 清空流量列表、从列表移除流量 | 直接执行，toast 给"撤销"（10 秒内） |
| 删除请求、文件夹、集合、环境、规则 | 直接执行，toast 给"撤销"；同时放进最近删除，保留到下次启动 |
| 关闭有未保存修改的 tab | 询问：保存 / 不保存 / 取消（现有行为） |
| 批量重放、Runner 运行有写操作的请求 | 先确认，说明会真的修改服务器数据（现有行为） |
| 开启系统代理、安装证书 | 用户主动点按钮才执行，执行前说明会改什么（现有行为） |
| 重置 Vault、清空 History | 先确认，说明不可恢复 |

## 8. 反馈

- **Toast**：操作结果。四个级别：信息、成功、警告、错误。可以带一个动作（撤销、查看、重试）。信息和成功 4 秒消失；警告和错误不自动消失，直到用户关闭或点了动作。同时最多显示 3 个，其余合并成"还有 N 条"。
- **错误**：一句话说明发生了什么、用户能做什么，加一个"详情"展开原始错误（可复制）。不要只显示原始错误。
- **进度**：超过 1 秒的操作显示进度（列表里的加载行、按钮上的转圈）；超过 5 秒的操作可以取消。
- **不静默失败**：保存失败、读取失败、被拒绝的导入，都必须有可见的反馈，并保留用户的输入。

## 9. 首次使用

第一次启动（`~/.vscroxy` 不存在）时，在工作区的空状态里显示一个分步引导，可以随时跳过，之后从命令面板重新打开：

1. **开始抓包**：显示监听地址；按钮"开启系统代理"，或者"只抓某个程序"（跳到终端、浏览器、设备的接入方式）。
2. **信任证书**：说明为什么需要；按钮"安装并信任"；完成后自动检查。
3. **选择要解密的对象**：列出已经看到的 App 和域名，勾选后开启 HTTPS 解密。
4. **完成**：看到第一条解密的请求时，高亮它，提示"点击查看详情"。

非首次启动、列表为空时，空状态只显示一句话和最多两个按钮（比如"开启系统代理"和"连接诊断"）。

## 10. 键盘

- 现有的快捷键表（见 `docs/guide.md` 的 Keyboard debugging）保持不变，新增快捷键不能和它冲突。
- 每个快捷键都显示在对应的菜单项、按钮 tooltip 和命令面板里。
- 焦点顺序：标题栏 → 侧栏 → 工具栏 → 主列表或编辑器 → 检查器或响应。Esc 逐级返回。
- 弹窗打开时焦点进入弹窗，关闭后回到打开它的控件。

## 11. 文案

### 语气和长度

- 句子式大小写（"Save as request"，不是 "Save As Request"），和现有界面一致。
- 按钮：动词开头，不超过 3 个词。
- 说明文字：一行，约 80 个字符以内；更多内容放进 tooltip 或"了解更多"。
- Tooltip：一句话，说明"做什么"，不重复按钮文字。
- 错误：说"发生了什么 + 怎么办"，不说"出错了"。
- 省略号 `…` 只用于"点了之后还要输入或确认"的菜单项和按钮，不用于工具栏图标按钮和 tab。
- 不在界面里讲实现细节（比如"spill file"、"first-match order"），这些放进文档。

### 术语表

界面、文档、代码注释里的同一个概念只用一个词。中文是之后翻译时的标准译名。

| 概念 | 英文 | 中文 | 不再使用 |
| --- | --- | --- | --- |
| 抓到的一次交换 | request（列表里）、exchange（文档里） | 请求 | flow（只留在代码里） |
| 选中多条 | select、selected | 选中 | choose、chosen、pick |
| 原样再发一次 | Replay | 重放 | Repeat、Resend |
| 编辑抓到的请求 | Edit request | 编辑请求 | Edit & replay、Edit & resend |
| 暂停记录 | Pause recording | 暂停录制 | |
| HTTPS 解密 | HTTPS inspection | HTTPS 解密 | SSL proxying（只在兼容说明里出现） |
| 已保存的请求 | request | 请求 | saved request、asset |
| 请求的集合 | collection | 集合 | |
| 环境 | environment | 环境 | |
| 规则 | rule | 规则 | |
| 规则分组 | scenario | 场景 | |
| Host 映射方案 | host profile | Host 方案 | DNS mapping（升级后不再用） |
| 保存的流量文件 | session | 会话 | investigation、evidence |
| 发送记录 | history | 历史 | run records、experiments、send history、debug history |
| 响应示例 | example | 示例 | |

| 断点 | breakpoint | 断点 | break |

## 12. 评审清单

每个新功能或改版，合并前检查：

- [ ] 它属于第 1 节的哪个核心任务？放的位置符合第 3 节吗？
- [ ] 如果它会改变流量，启用时会出现在已启用工具栏里吗？
- [ ] 它的动作在动作表里吗？右键、`⋯`、命令面板、快捷键是否一致？
- [ ] 选的交互模式符合第 4 节吗？有没有弹窗叠弹窗？
- [ ] 破坏性操作是撤销还是确认，符合第 7 节吗？
- [ ] 成功、失败、进度都有反馈吗？失败时保留了用户输入吗？
- [ ] 空状态、加载、错误三种状态都设计了吗？
- [ ] 文案符合第 11 节吗？用的是术语表里的词吗？有没有超过一行的说明？
- [ ] 只用键盘能完成吗？焦点顺序和 Esc 行为对吗？
- [ ] 浅色、深色截图都检查过吗？
